# Nord Coffee — premium coffee shop website

Коммерческий одностраничный сайт кофейни Nord Coffee, собранный на чистом HTML5, CSS3 и JavaScript без UI-фреймворков.

## Технологии

- HTML5 — семантическая структура, SEO и accessibility
- CSS3 — responsive layout, CSS Grid/Flexbox, transitions, adaptive breakpoints
- Vanilla JavaScript — мобильное меню, scroll-state, reveal-анимации, active navigation и валидация формы
- Google Fonts — DM Sans + Manrope
- Unsplash — демонстрационные фотографии через CDN

## Структура

```text
Nord-Coffee/
├── index.html   # разметка и контент
├── style.css    # дизайн-система и адаптивные стили
├── script.js    # интерактивность и валидация
└── README.md    # документация проекта
```

## Реализованные функции

- Hero-блок с CTA
- фиксированный header, меняющийся при прокрутке
- desktop navigation и mobile hamburger menu
- закрытие mobile menu по клику, Escape и переходу на desktop
- активный пункт навигации по текущей секции
- меню кофе / десертов / завтраков
- блок «О нас»
- четыре преимущества
- адаптивная editorial-фотогалерея
- отзывы
- форма бронирования
- обязательные поля и проверка телефона
- запрет выбора даты в прошлом
- inline-сообщения об ошибках через `aria-invalid`
- сообщение об успешной демонстрационной отправке
- контактный блок и CSS-карта
- плавный scroll и reveal-анимации
- поддержка `prefers-reduced-motion`
- skip-link, focus states, semantic landmarks и alt-тексты
- SEO title и meta description
- responsive layouts для мобильных, планшетов и desktop

## UX/UI решения

Визуальное направление — warm Nordic editorial: графит, молочный фон, кофейный акцент, крупная типографика, асимметричная сетка и сдержанные micro-interactions. Секции имеют выраженную иерархию, а коммерческие CTA повторяются в логичных точках пользовательского пути.

## Ограничения демонстрационной версии

1. **Бронирование не подключено к backend.** После успешной клиентской валидации форма только показывает сообщение и очищается. Для production нужен API/CRM или reservation-сервис.
2. **Карта — CSS placeholder.** Для реального адреса следует подключить Google Maps, Mapbox, OpenStreetMap или другой картографический сервис.
3. **Социальные ссылки — демонстрационные.** В ТЗ не были указаны реальные аккаунты Nord Coffee, поэтому перед публикацией их нужно заменить на официальные URL бренда.
4. **Фотографии — Unsplash CDN.** Для коммерческого релиза желательно заменить их на собственные/licensed assets и при необходимости локально оптимизировать в WebP/AVIF.
5. **Google Fonts** загружаются внешне; при строгих требованиях к privacy/performance их можно self-host.
6. Нет cookie-consent/analytics/legal pages — они зависят от реального способа публикации и юрисдикции.

## Production checklist

- подключить backend/API бронирования;
- заменить demo social URLs и фотографии;
- добавить реальные favicon/OG image и production canonical после появления домена;
- подключить analytics только после определения privacy/legal требований;
- проверить Lighthouse/PageSpeed на production CDN;
- настроить CSP, HTTPS, caching и compression на сервере.

## Запуск

Откройте `index.html` в браузере либо запустите любой static server. Для проекта без сборщика дополнительные npm-зависимости не требуются.


## Visual & commercial audit

Финальная визуальная ревизия сфокусирована на коммерческой ясности без добавления лишних блоков.

- Убран неподтверждённый `EST. 2021`; hero теперь сразу формулирует позиционирование: specialty coffee, breakfast, Berlin.
- Исправлена информация в hero: часы соответствуют контактному блоку для будней и выходных.
- Фото-блок меню теперь использует реальную позицию из меню — Flat White за 4.20 €, вместо вымышленного сезонного продукта.
- Увеличена читаемость вторичного текста и тела контента; интерактивные пункты desktop-навигации получили более удобную область клика.
- Форма бронирования получила более аккуратный визуальный контейнер и заметное состояние focus.
- На мобильных уменьшена избыточная высота первого экрана и слегка сокращены карточки отзывов, чтобы быстрее доводить пользователя до следующего полезного действия.

Эти изменения не добавляют новые сущности или декоративные блоки — они усиливают существующую концепцию и коммерческую достоверность.
